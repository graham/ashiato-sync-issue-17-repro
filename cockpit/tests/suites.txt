# EVERY TEST SUITE IN THE PROJECT, IN THE ORDER THEY RUN.
#
# Read by BOTH runners -- tests/run_all.sh and tests/run_all.ps1 -- because two lists went
# out of step. The PowerShell one was missing `water` and `air` for as long as they have
# existed, so a Windows run reported all-green over two suites it had never heard of. A
# list kept in two places is a list kept in one place and a copy of it.
#
#   name   project   scene   [seconds]   [tiers]
#
# THE LAST COLUMN IS THE SUITE'S TIERS, comma-separated, and `run_all.ps1 -Tier <tier>` runs every
# row that has it (lane/gate, 2026-09-19). A row may have a deadline, tiers, both or neither; a
# number is a deadline and a word is a tier, and a word that is not one of these three stops the
# runner, so a typo cannot drop a suite from a gate in silence.
#
#   core   optional: the cheap suites that walk EVERY craft and seat at once, plus lint, docs, smoke
#          and the two-peer basics. 216 s at -Jobs 8 under load, 626 s one at a time. Worth adding to a
#          lane's own suites when its change is drawn on every craft: the Apache's helmet sights in
#          pilot_seat and a holstered lamp in front of a gauge in water were both red on main on
#          2026-09-19 after green targeted gates.
#   net    the peer and wire suites, and every extension suite: added to core by a lane that touches
#          C++, the wire, a synchroniser or anything a joiner sees.
#   solo   runs by itself after everything else, and once more if it fails, because its own checks
#          time the wall clock or wait for a second engine to start inside a window: under a loaded
#          machine these went red on load alone (hitch 31 times, bulk_peers 47, notices 27 in the
#          logs; voice_thread's 35 ms "queued without blocking" beside seven others on 2026-09-19).
#          A PASS on that second go is printed `PASS on retry (load)`, never hidden.
#
#          `builder_peers` JOINED THEM ON 2026-09-19, and it is the one to look at when deciding whether a suite wants
#          this tier. It had `net` alone while every other peers suite that waits for a second engine had `net,solo`,
#          so when it went red in a parallel batch -- EIGHT checks at once, admission, relay, refusal and save all
#          together, on a desk carrying two other lanes' captures -- the runner had no reason to try it again and the
#          whole gate read as one genuine failure. It passes ALONE in 28.4 s. Eight unrelated checks failing at once is
#          the signature of the machine and not of the code: a real fault takes out one thing.
#          THE USER'S RULE (2026-09-19): a suite that fails in the parallel batch and passes run on
#          its own counts as CLEAN, but it is INVESTIGATED (todo/sweeper--flaky-suites-under-load.md)
#          and it joins this tier, so it runs one at a time from then on. The sweeper's passes put
#          craft_peers, sweep_peers, no_vr_flight, crew_peers and record_shelf here on that evidence.
#
# A lane gates on its own suites, the ones it wrote, lint and docs. Every row is the sweeper's, on
# main, after features land: see running_a_team_here.md, section 4, "THE GATE POLICY".
#
# `project` is `cockpit` for the suites that test the game and `addon` for the ones that
# test the extension underneath it.
#
# THE FOURTH COLUMN IS THAT SUITE'S OWN DEADLINE IN SECONDS and almost no row needs one: a
# deadline is a guard against a HANG, not a performance budget, and 180 seconds is plenty for
# a suite that does one thing. Two rows have one because they are structurally slower than
# the rest -- `ship_legs` and `level_swap` walk EVERY usable level, so every level anyone adds
# lengthens those two and nothing else.
#
# `world_edge` WAS GIVEN 300 HERE ON 2026-09-19 AND IT WAS TAKEN AWAY AGAIN, which is worth a
# line because the reasoning was wrong in an instructive way. It timed out at 180 in a parallel
# batch and at 300 in the next one, and the story wrote itself: it flies every powered wing out
# and back, so the thirty-seventh kind must have pushed it over. MEASURED ALONE it takes 65.3 s
# with thirty-seven kinds and 68.7 s with thirty-six -- the new kind costs it nothing, and 180 is
# already the file's own rule of twice the measurement rounded up. The timeouts were two lanes
# running full gates on one machine at once. A DEADLINE IS A GUARD AGAINST A HANG: raising one
# because a loaded desk was slow buys nothing and blinds the guard. Measured on 2026-09-17 when the stress level made a
# sixth: ship_legs 125.7 s with five levels and 197.9 s with six, past the 180 it had always
# had. The values here are TWICE the measured time, rounded up to the next whole minute, so a
# loaded desk does not trip them and a real hang is still caught in about twice the honest
# runtime. Raising the deadline for EVERY suite instead would have hidden that the gate grows
# with the game, and left the next lane to find it the same way. Order matters at the top and nowhere else: `lint`
# compiles every script in the project in one second, so a typo is a red line rather than a
# three-minute timeout, and `fit` measures every cockpit before anything tries to sit in one.
